# Decision Record

This directory keeps a record of decisions made about specific choices on how a Cloud Native Rejekts event should be run.

These decision records are loosely based on Architecture Decision Record (ADR)s, but they are not strictly ADRs. They are intended to provide a clear and concise way to document the reasoning behind decisions made in the context of Cloud Native Rejekts and work as guiding principals for what makes a Cloud Native Rejekts conference.

## Structure

Each file in this directory represents a decision record. Each file should contain the following information:

```
#  A brief title.

**Status**: The status of the decision record, such as "Approved", "Pending", "Rejected", "Deprecated", or "Superseded".

**Description**: A detailed description of the decision, including any relevant context and reasoning behind it.

- **Resources** (Optional): Any resources used in the decision-making process that may add more context for future readers.
```

## Example

> # Using Decision Records
>
> **Status:** Approved
>
> To ensure decisions made are transparent and easily understandable, we have adopted a structured approach to documenting our decisions. This includes using decision records, which provide a clear and concise way to document the reasoning behind decisions made in the context of Cloud Native Rejekts.
>
> We believe that this approach will help improve collaboration among team members and ensure that everyone is on the same page regarding what makes a Cloud Native Rejekts event.
